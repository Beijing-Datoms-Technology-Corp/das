# DAS 安全机制详解

## 概述

DAS 实现了企业级的安全机制，确保数据资产的完整性、真实性和不可篡改性。所有核心功能都建立在加密技术之上。

## 核心安全组件

### 1. RSA 数字签名

#### 密钥生成
```bash
# 生成 2048 位 RSA 密钥对
私钥: ~/.das/keys/private.pem (安全存储)
公钥: workspace/cert.pub (分发使用)
```

#### 签名流程
```
原始数据 → SHA256 哈希 → RSA 私钥签名 → 数字签名
```

#### 验签流程
```
数字签名 → RSA 公钥验证 → 原始数据哈希 → 完整性确认
```

### 2. 数据完整性保护

#### 文件哈希计算
- **算法**: SHA256
- **范围**: 工作区所有数据文件
- **存储**: `hashes.json` (包内)

#### 哈希字符串格式
```
path/to/file1:sha256_hash_value
path/to/file2:sha256_hash_value
...
```

### 3. 包结构安全

#### 压缩包格式
```
data.das.gz/
├── manifest.json      # 项目元数据
├── graph.json         # 关系图数据
├── assets/            # 原始数据文件
├── hashes.json        # 文件完整性哈希
└── _signature.sig     # RSA 数字签名
```

## 安全工作流程

### 1. 密钥管理

#### 初始化阶段
```bash
1. 生成 RSA 密钥对
2. 私钥存储在安全位置 (~/.das/keys/)
3. 公钥复制到工作区 (cert.pub)
```

#### 安全注意事项
- ✅ 私钥文件权限: `600` (仅所有者可读写)
- ✅ 私钥永不离开本地机器
- ✅ 公钥可安全分发和分享
- ❌ 私钥不应提交到版本控制
- ❌ 私钥不应通过网络传输

### 2. 数据打包

#### 打包流程
```bash
1. 收集所有工作区文件
2. 计算每个文件的 SHA256 哈希
3. 生成哈希字符串 (排序保证一致性)
4. 使用私钥对哈希字符串签名
5. 创建 TAR 归档文件
6. GZIP 压缩
7. 输出 .das.gz 文件
```

#### 安全保证
- 🔐 **完整性**: 任何文件修改都会改变哈希
- 🔐 **真实性**: 只有私钥持有者能生成有效签名
- 🔐 **不可否认**: 签名证明数据来源

### 3. 包验证

#### 验证流程
```bash
1. 解压 .das.gz 文件
2. 读取签名文件 (_signature.sig)
3. 重新计算所有文件的哈希
4. 使用公钥验证签名
5. 比较计算哈希和签名哈希
```

#### 验证结果
- ✅ **签名有效**: 包完整且来自可信来源
- ❌ **签名无效**: 包被篡改或来源不可信
- ⚠️ **公钥缺失**: 无法验证，需要获取公钥

## 威胁模型

### 1. 数据篡改攻击

**攻击方式**: 修改包内文件内容
**防御措施**:
- SHA256 哈希检测文件变化
- RSA 签名防止哈希伪造

**风险等级**: 🔴 高 → ✅ 通过哈希验证解决

### 2. 身份伪造攻击

**攻击方式**: 伪造数据来源
**防御措施**:
- RSA 私钥签名确保来源真实性
- 公钥分发机制

**风险等级**: 🔴 高 → ✅ 通过数字签名解决

### 3. 重放攻击

**攻击方式**: 重用旧的签名
**防御措施**:
- 哈希包含文件内容变化
- 每次打包生成新的哈希

**风险等级**: 🟡 中 → ✅ 通过内容哈希解决

### 4. 中间人攻击

**攻击方式**: 拦截和修改传输中的包
**防御措施**:
- 建议使用 HTTPS/TLS 传输
- 接收方必须验证签名

**风险等级**: 🟡 中 → ✅ 通过端到端验证缓解

## 密钥生命周期管理

### 1. 密钥生成

```bash
# 推荐的密钥参数
算法: RSA
密钥长度: 2048 位 (最小)
格式: PKCS#8 (私钥), SPKI (公钥)
```

### 2. 密钥存储

#### 私钥安全存储
- **位置**: `~/.das/keys/private.pem`
- **权限**: `600` (仅用户可读写)
- **备份**: 加密备份到安全位置
- **轮换**: 定期更换 (推荐: 1-2 年)

#### 公钥分发
- **位置**: 工作区根目录 `cert.pub`
- **用途**: 包验证和分发
- **更新**: 密钥更换时同步更新

### 3. 密钥轮换

```bash
1. 生成新密钥对
2. 使用新私钥重新签名所有包
3. 分发新公钥
4. 安全删除旧私钥
5. 更新所有相关文档
```

- 🔐 **定期轮换**: 至少每年更换一次密钥
- 🔐 **安全备份**: 加密备份私钥到离线存储

### 2. 操作安全

- ✅ **验证签名**: 接收包前始终验证签名
- ✅ **安全传输**: 使用加密通道传输包
- ✅ **完整性检查**: 定期检查已归档包的完整性
- ✅ **备份策略**: 实施可靠的备份和恢复策略

### 3. 应急响应

#### 密钥泄露处理
```bash
1. 立即停止使用泄露密钥
2. 生成新密钥对
3. 重新签名所有活动包
4. 通知所有相关方
5. 吊销旧公钥
```

#### 数据损坏恢复
```bash

2. 使用新密钥重新打包
3. 验证新包签名
4. 更新所有引用
```

## 故障排除

### 签名验证失败

**可能原因**:
- 公钥不匹配
- 数据被篡改
- 传输过程中损坏

**解决步骤**:
1. 确认使用正确的公钥
2. 检查文件完整性
3. 从可信来源重新获取包

### 密钥访问问题

**可能原因**:
- 权限设置错误
- 密钥文件损坏
- 存储位置错误

**解决步骤**:
1. 检查文件权限
2. 验证密钥文件完整性
3. 重新生成密钥对

## 技术实现细节

### 密码学算法

- **对称加密**: 不使用 (密钥分发问题)
- **非对称加密**: RSA-2048
- **哈希函数**: SHA256
- **签名格式**: RSASSA-PKCS1-v1_5

### 性能考虑

- **密钥大小**: 2048 位平衡安全性和性能
- **哈希计算**: 流式处理避免内存溢出
- **签名验证**: 快速的公钥操作

### 兼容性

- **Node.js**: 原生 crypto 模块
- **浏览器**: Web Crypto API (计划中)
- **跨平台**: 所有主流操作系统支持
